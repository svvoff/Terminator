# Индекс валидации

## Философия

Исполнитель не может заявить успех без доказательств. Оркестратор не может принять работу без
их проверки. «Прошло» без вывода команды доказательством не является.

## Словарь профилей — закрытый

Каждая готовая карточка несёт `validation_profile` во фронтматтере. Токенов ровно три, других
не бывает. Если в карточке появился четвёртый — это ошибка карточки, а не расширение словаря.

| Токен | Уровень | Что означает |
|---|---|---|
| `swift-build` | L0 | `swift build` зелёный. Для карточек, собирающих бандл, дополнительно: `./build.sh` завершается успешно, и его терминальный шаг — `codesign --verify --strict`. |
| `swift-test` | L1 | `swift test` зелёный, включая тесты, которые карточка называет поимённо. |
| `manual-checklist` | L5 | Нумерованный чеклист самой карточки выполняет автор на своей машине, результаты записываются. Исполнитель это **не засчитывает** — он останавливается и сообщает. |

Карточка без `manual-checklist` должна полностью проверяться исполнителем без человека за
клавиатурой. Карточка с ним всегда явно называет, на что должен посмотреть человек.

## Команды проекта

| Команда | Когда обязательна | Заметки |
|---|---|---|
| `swift build` | `swift-build` | Отладочная сборка. TASK-004 требует ещё и `-c release`. |
| `swift test` | `swift-test` | Тесты ядра идут без sleep и без реального времени: тест, которому нужно ждать, — дефект дизайна, а не медленный тест. |
| `./build.sh` | карточки, собирающие бандл | Собирает `build/Terminator.app` руками и подписывает **последним** шагом. |
| `codesign --verify --strict build/Terminator.app` | там же | Терминальный шаг сборки; его код возврата и есть проверка (findings §6). |
| `codesign -d -r- build/Terminator.app` | подпись и идентичность | Designated requirement до и после пересборки, дословно. |
| `security find-identity -v -p codesigning` | работа с подписью | Должна быть видна `Terminator Dev`. |
| `scripts/verify-docs.sh` | перед выбором задачи | Согласованность бэклога; ERROR чинится до выбора. |
| `scripts/check-forbidden.sh` | `swift-build` и `swift-test` | Грep-гейты по исходникам (см. ниже). |

**Все команды из таблицы существуют и зелёные.** `Package.swift` и `build.sh` появились в
TASK-002, первый тестовый таргет — в TASK-003 (22 теста в четырёх сьютах). Уровень L5 больше не
единственный доступный: TASK-003 стала первой карточкой, проверенной целиком без человека за
клавиатурой.

## Грep-гейты

Часть запретов проекта проверяется механически, и карточки этого прямо требуют (TASK-004,
раздел Validation requirements). `scripts/check-forbidden.sh` кодирует их один раз, чтобы
список не переписывался в каждой карточке и не расходился.

По всему дереву исходников: `forceTerminate`, `.terminate()`, `SIGTERM`, `SIGKILL`, `kill(`,
`beginActivity`, `===` против `NSRunningApplication`, `@unchecked Sendable`,
`@preconcurrency import`, `swiftLanguageMode(.v5)`, `UserDefaults`, `Bundle.module`,
`swift run`.

Дополнительно по `Sources/TerminatorCore/`: `import AppKit`, `ContinuousClock`, `DispatchTime`,
протокол `Clock`.

Скрипт возвращает 0, пока `Sources/` не существует, — до TASK-002 он не должен мешать.

Гейты, которые грепом не выражаются, и потому живут в `docs/ai/review-checklist.md`:
`SuspendingClock` **в пути дедлайна** (само по себе оно разрешено — TASK-007 добавляет
suspending-чтение для накопления фокуса), `Date()` внутри разрешения времени запуска, и
`privacy: .public` на каждой интерполяции в логах.

## Матрица задач Stage 1

| Задача | Риск | Профиль | Что это значит на практике |
|---|---|---|---|
| TASK-001 | high | `manual-checklist` | Человек за клавиатурой. Не делегируется. Продуктового кода не производит. |
| TASK-002 | medium | `swift-build` + `manual-checklist` | Первая сборка бандла. Юнит-тестов не добавляет намеренно — их отсутствие здесь не пробел. |
| TASK-003 | low | `swift-build` + `swift-test` | Полностью проверяется без человека. |
| TASK-004 | high | `swift-build` + `swift-test` + `manual-checklist` | Плюс `swift build -c release` и грep-гейты. |
| TASK-005 | medium | `swift-build` + `swift-test` + `manual-checklist` | Диалоги согласия — интерактивные. |
| TASK-006 | medium | `swift-build` + `swift-test` + `manual-checklist` | Меню-бар виден только человеку. |
| TASK-007 | medium | `swift-build` + `swift-test` + `manual-checklist` | |
| TASK-008 | low | `swift-build` + `swift-test` + `manual-checklist` | LaunchAgents — правка домашнего каталога. |
| TASK-009 | high | `manual-checklist` | Спайк на живых приложениях. Продуктового кода не производит. |

Семь карточек из девяти несут `manual-checklist`. Это свойство продукта, а не недоработка
бэклога: TCC, подпись и меню-бар не проверяются headless, и карточки говорят об этом прямо
вместо того, чтобы изобретать headless-суррогат.

## Политика падений

1. Определи, вызвано ли падение текущим изменением, и приложи доказательство.
2. Не чини посторонние падения без отдельного поручения.
3. Не удаляй, не пропускай и не глуши тесты и проверки, чтобы стало зелено.
4. Если падение базовое (было до изменения) — сообщи, и оркестратор решит, нужна ли отдельная
   карточка.
