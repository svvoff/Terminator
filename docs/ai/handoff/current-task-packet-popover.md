## Почему раунд 4

Единственное расширение скоупа в истории этой карточки, и оно решено автором. Строка списка
опознаёт приложение только по bundle id, моноширинным шрифтом с усечением по середине, поэтому
`com.apple.printcenter` читается как `com.appl…intcenter`, а `org.khronos.gltf.glTFViewer` — как
`org.khro…lTFViewer`. Автор не может понять с одного взгляда, о чём строка.

## Что менять

### 1. Резолв имени — в `PopoverModel`, с кэшем на открытие

`NSWorkspace.shared.urlForApplication(withBundleIdentifier:)` → `FileManager.default.displayName(atPath:)`.

Резолв делается в `popoverDidOpen()`, **после `reloadFromDisk()`** (иначе правило, дописанное в
файл руками, останется без имени), результат кладётся в словарь по bundle id и живёт до
следующего открытия.

**Ловушка производительности:** содержимое поповера перерисовывается **раз в секунду** ради
отсчёта. Резолв внутри `body` вью или на каждую перерисовку — обращение к LaunchServices на
каждый кадр за значением, которое при открытом поповере не меняется. Дисциплина та же, что уже
применена к статусу автозапуска: одно чтение на открытие, а не на кадр.

**Ловушка выбора API, из-за которой этот пакет написан отдельно.** НЕ читай `CFBundleDisplayName`
и не откатывайся на `CFBundleName`. Измерено на четырёх настоящих правилах автора:

| Bundle id | `CFBundleDisplayName` | `CFBundleName` | `displayName(atPath:)` |
|---|---|---|---|
| `com.apple.TextEdit` | TextEdit | TextEdit | TextEdit |
| `com.tdesktop.Telegram` | **нет** | Telegram | Telegram |
| `org.khronos.gltf.glTFViewer` | **нет** | **нет** | glTF Viewer |
| `com.apple.printcenter` | Print Center | Print Center | Print Center |

`CFBundleDisplayName` отсутствует у двоих из четырёх, `CFBundleName` — у одного: это обёрнутое
iOS-приложение, у которого нет `Contents/Info.plist` на верхнем уровне вовсе. Реализация через
ключи Info.plist выглядит правильной и молча не работает на трети списка.

### 2. Строка в `PopoverView`

Сейчас primary — `Text(row.bundleIdentifier)` (`PopoverView.swift:163`), моноширинный,
`.truncationMode(.middle)`, с `.help(...)`. Становится:

- **primary** — имя приложения, обычным body-шрифтом, **не моноширинным**. `.help(...)` с полным
  bundle id сохраняется;
- **вторичная область, первая строка** — bundle id: caption, моноширинный, `.secondary`, с тем же
  отступом, что у существующих статусных строк;
- **ниже** — существующие статусные строки без изменений (`not running`, `off`, либо по одной
  строке остатка на каждый запущенный экземпляр).

Bundle id остаётся видимым намеренно: это точный ключ сопоставления (findings §10), он же лежит в
`config.json`, который автор правит руками, и он же печатается в каждой строке лога.

**Отдельная строка, а не приписка `com.tdesktop.Telegram · off`.** Приписка хорошо читается в
ветке без экземпляров и разваливается во второй, где статусных строк столько же, сколько
запущенных экземпляров.

### 3. Имя не резолвится

Приложение не установлено — случай настоящий, правило переживает удаление приложения. Тогда
**primary показывает bundle id**, как сегодня, а вторичная строка с идентификатором **не
выводится**: одна и та же строка не должна стоять дважды.

## Чего не делать

- **Не трогать `TerminatorCore`.** `PopoverViewModel` и `PopoverRow` не меняются: имя — это
  presentation, оно не участвует ни в сортировке, ни в фильтрации, ни в одном решении.
- **Не менять сортировку.** Порядок остаётся по остатку и затем по `bundleIdentifier`, никогда по
  имени. Тест `equalRemainingTimesBreakTieByBundleIdentifier` обязан остаться зелёным.
- Имя **не сохраняется** в `config.json`. Это сменило бы человекочитаемый контракт на диске
  (миграция, зона 6) ради значения, которое протухает.
- Новых строк лога не добавлять.
- Иконок приложений, поиска, группировки, переименования вручную — ничего этого нет.
- Не трогать `NSApp.activate()` и валидатор панели из раундов 2 и 3.

## Валидация

| Команда | Что доказывает |
|---|---|
| `swift build` | отладочная сборка, **ноль строк `warning:`** |
| `swift build -c release` | релизная сборка, **ноль строк `warning:`** |
| `swift test` | **ровно 83 теста в 8 сьютах** — этот раунд тестов не добавляет и не убирает |
| `scripts/check-forbidden.sh` | греп-гейты |
| `./build.sh` | терминальный шаг — `codesign --verify --strict` |

Приложи вывод команд и отдельно счётчики `warning:` для обеих конфигураций.

**Юнит-теста нет:** резолв зависит от `NSWorkspace`, LaunchServices и того, что установлено на
машине; мок-`NSWorkspace` запрещён не-целями карточки. Не выноси резолв в ядро ради
тестируемости — ядро окружение не читает по конструкции.

## Ручной чеклист ты НЕ засчитываешь

Доказательство — новый пункт 16: каждая строка показывает читаемое имя над bundle id,
`com.apple.printcenter` читается как *Print Center*, `org.khronos.gltf.glTFViewer` — как
*glTF Viewer*, а правило неустановленного приложения показывает идентификатор и не показывает
пустое имя. Приложение не запускай.

## Стоп-условия

1. Если резолв потребует тронуть `TerminatorCore` — остановись и объясни, не расширяй скоуп.
2. Если `urlForApplication(withBundleIdentifier:)` окажется недоступен без энтайтлмента или
   поднимет диалог согласия — остановись и доложи с доказательством.
3. Любая строка `warning:` — стоп. Изменение числа тестов — тоже стоп.
