# Чеклист ревью

Ревью выполняет оркестратор — независимого ревьюера в проекте нет. Отсюда первое правило:
**сначала дифф, потом отчёт**. Ты уже видел, как писался пакет, и склонен принять объяснение
исполнителя о том, почему код правильный; чтение отчёта первым закрепляет эту склонность.

## Порядок

Дешёвое и частое — первым.

1. **Скоуп.** Каждый файл диффа против Allowed / Forbidden areas пакета. Файл вне зоны —
   blocker независимо от качества правки.
2. **Acceptance criteria** по пунктам: выполнен / частично / не выполнен. Молча пропущенный
   пункт — находка.
3. **Расхождение отчёта и диффа.** Отчёт утверждает одно, дифф показывает другое.
4. **Доказательства.** Для каждой обязательной команды приложен вывод.
5. **Проектные правила** (ниже).
6. **Существо.** Границы, флаки, протечка состояния между тестами.

Уровни: `blocker` / `major` / `minor` / `nit`. Занижение уровня из вежливости — дефект ревью.

## Проектные правила, которые грепом не ловятся

Это то, ради чего ревью и существует: список запретов проверяет скрипт, а вот эти четыре —
только человек или модель, читающая код.

1. **`privacy: .public` на каждой интерполяции в логах.** Пропуск даёт `<private>` в момент
   записи, невосстановимо. Предупреждений перед закрытием нет (DEC-004), поэтому лог —
   единственный ответ на «почему оно закрылось» (§14).
2. **`SuspendingClock` в пути дедлайна.** Сам по себе тип разрешён — TASK-007 добавляет
   suspending-чтение для накопления фокуса. Запрещено именно его участие в вычислении
   дедлайна: дедлайн живёт на шкале `Date` и входит в ядро как `Now.wall` (§9).
3. **`Date()` внутри разрешения времени запуска процесса.** Время старта берётся из
   `p_starttime` (§3).
4. **Кэширование pid через границу использования.** `processIdentifier` изменяем на живом
   объекте; перед отправкой события pid перечитывается и сверяется с bundle id (§10).

## Измерения против решений

- Ни одно утверждение в правках `macos-findings.md` не сформулировано как «должно»,
  «по документации» или «как и ожидалось». Findings — измерения; фраза без наблюдения за
  спиной отклоняется.
- Если результат противоречит карточке решения — исполнитель остановился и эскалировал, а не
  выбрал обходной путь. Тихо изменённая схема подписи или ослабленный гейт — отказ.
- Карточки решений исполнителем не правились.

## Скоуп вехи

- MVP не расширен под будущие стадии. Статистика, расписания, cooldown, дневной бюджет,
  дистрибуция не реализованы, не заглушены и не спрятаны за флаг.
- Две разрешённые уступки будущему на месте: лимит — правило в версионированном JSON, действие
  на истечение — сменная стратегия. Больше ничего.

## Решение

Одно из: `ACCEPT` / `REQUEST_CHANGES` / `BLOCKED` / `ESCALATE_TO_USER` / `REVERT_OR_ROLLBACK`.

`BLOCKED` — когда падает окружение и в коде чинить нечего. `REQUEST_CHANGES` — когда менять
надо реализацию.

Нет доказательств валидации — нет приёмки.
